# PPT용 기술 스택·사용 기술 정리

발표 슬라이드에 바로 옮겨 쓸 수 있게 항목별로 정리. 현재 코드(2026-07-29, main) 기준.

## 1. 한 줄 소개

자율주행 모바일 로봇(pinky pro)이 상품을 진열대 앞까지 운반하고, 모방학습된 로봇팔(SO-ARM101)이 상품을 지정 칸에 진열하는 무인 상품 진열 시스템.

## 2. 기술 스택 한눈에

| 분야 | 기술 | 용도 |
|---|---|---|
| OS / 미들웨어 | Ubuntu 24.04, ROS2 Jazzy (Python 3.12) | 전체 시스템 기반, 노드 간 통신(DDS) |
| 자율주행 | Nav2 (AMCL, map_server, planner) | SLAM 지도 기반 목적지 주행 |
| 모방학습 | LeRobot + ACT (Action Chunking Transformer) | 로봇팔 진열 동작 학습·추론 |
| 학습 인프라 | RTX 5090 서버 (torch 2.7+ / CUDA 12.8+) | ACT 정책 원격 학습 (rsync + ssh) |
| 웹 백엔드 | FastAPI + uvicorn | REST + WebSocket + MJPEG 스트림 |
| 웹 프론트 | 순수 HTML/JS 한 장 (index.html) | 시연 UI: 4분할 캠 + SLAM 지도 + 코스트맵 오버레이 |
| 카메라 | OpenCV(USB 캠), picamera2(핑키 CSI 캠) | 정책 입력·웹 스트림 |
| 텔레옵 | joy + 자체 teleop_racing 노드 | 엑스박스 컨트롤러 조종·녹화용 주행 |
| 빌드/테스트 | colcon (ament_python), pytest | 워크스페이스 빌드, 상태머신·웹 단위 테스트 |

## 3. 시스템 아키텍처 포인트 (슬라이드 1장감)

- **분산 실행**: 핑키 온보드는 pinky_bringup(모터·라이다·odom/tf)만 실행, Nav2 전체는 노트북에서 실행 — 라즈베리파이 연산 부담을 노트북으로 이전. ROS2 DDS로 WiFi 통신.
- **두 파이썬 환경의 프로세스 분리**: rclpy(시스템 파이썬) ↔ torch/LeRobot(별도 venv)은 의존성이 충돌하므로 한 프로세스에 두지 않고, orchestrator가 진열 시점에 `run_policy_wrapper.sh`를 서브프로세스로 호출. 종료코드로 성공/실패 판정.
- **단일 프로세스 orchestrator**: 상태머신 ROS 노드 + uvicorn 웹 서버를 한 프로세스(스레드 분리)로 — 배포·시연 단순화.

## 4. 사용 기술 상세

### 자율주행 (Nav2)
- 사전 제작한 SLAM 지도(gukbab_map) 위에서 AMCL 위치추정 + NavigateToPose 액션으로 진열대 앞 goal 주행.
- Nav2 파라미터는 pinky_navigation 기본값을 복사해 `nav2_params.yaml`로 관리, 웹 UI에서 주요 파라미터 실시간 튜닝 가능.
- 안전 규칙: `cmd_vel` 퍼블리시 코드는 항상 속도 클램프 + 종료 시(예외 포함) 0 퍼블리시 보장.

### 모방학습 (LeRobot ACT)
- 관측: 손목캠 등 카메라 영상 + SO-ARM101 관절 상태 / 행동: 관절 목표치 (LeRobot 표준).
- 텔레옵 시연 데이터를 녹화(record.sh) → 5090 서버로 rsync 후 원격 학습(train_remote.sh) → 체크포인트를 lerobot-rollout으로 추론.
- 정지 신호(SIGTERM) 시 초기 자세 복귀까지 rollout 프레임워크가 처리 — 비상 정지 안전성.

### 상태머신 (orchestrator)
- READY → NAVIGATING → PLACING → DONE / FAILED. 순수 파이썬 모듈로 분리해 ROS 없이 pytest 단위 테스트.
- 단계별 타임아웃(주행 120s, 진열 90s)과 실패 사유 기록, FAILED에서 실패 단계부터 재시도(/retry) 지원.

### 웹 UI (시연 화면 그 자체)
- FastAPI 하나로 REST(시작/정지/재시도) + WebSocket(상태 실시간 브로드캐스트) + MJPEG(multipart) 스트림 제공.
- SLAM 지도 PNG 위에 로봇 위치(/amcl_pose)·경로(/plan)·코스트맵 오버레이 렌더.
- **Frame Hub**: USB 캠은 프로세스당 하나만 열 수 있으므로 단일 리더 스레드가 캠을 점유하고 웹 스트림·정책 입력에 프레임 분배 — 장치 경합 원천 차단.

### 핑키 카메라 스트림 (엔지니어링 판단 사례)
- 핑키 CSI 캠은 V4L2 캡처 불가, raw 이미지 토픽은 WiFi 대역폭 초과 → ROS 토픽 대신 핑키에서 picamera2 MJPEG HTTP 서버를 직접 띄우고 웹 UI가 URL 직결. "가장 가벼운 경로" 선택.

### 텔레옵 (데이터 수집·수동 조종)
- 엑스박스 컨트롤러, 레이싱 게임 방식: RT 가속·LT 브레이크/후진·왼스틱 조향·A/X 기어 — 직관적 조작으로 녹화 품질 확보.

## 5. 개발 프로세스 (선택 슬라이드)

- 설계 SSoT 문서(구현계획서) 기반 구현, 상태머신·웹은 pytest 단위 테스트 유지.
- 반복 개선 이력: 아루코 마커 도킹 → Nav2 정밀 goal로 단순화(구조 축소), 탑뷰 캠 3역 구조 → 제거, ROS 토픽 스트림 → HTTP 직결 등 "동작하는 최소 구조"로 수렴.
